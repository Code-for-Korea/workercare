# 분석 통계표 재생성 (`analysis:report`)

`wip/workercare-hermes.md` [A]의 통계표를 로컬 DB 질의만으로 다시 만드는 방법이다. LLM·외부 API·임베딩 서비스를 쓰지 않고, DB는 읽기만 한다(`ActiveRecord::Base.while_preventing_writes`). 판정서 본문은 어디로도 나가지 않는다.

```bash
bin/rails analysis:report                       # tmp/analysis/report-YYYYMMDD.md (gitignore)
bin/rails "analysis:report[/path/to/report.md]"
```

구현은 `app/models/analysis_report.rb`(`AnalysisReport.new(scope:).to_markdown`), 테스트는 `test/models/analysis_report_test.rb`다. 개발 DB 61,815건에서 몇 초 걸린다.

## 무엇이 재현되고 무엇이 안 되는가

| hermes [A] 절 | 상태 | 비고 |
|---|---|---|
| 1 핵심 요약, 2.1·2.2, 3, 5.1·5.2, 7 | 재현 | 2026-11-12 개발 DB 값이 hermes와 같다(아래 오차 제외) |
| 2.3 신청서 종류, 4.3 근무 형태 | 재현하되 분포가 다르다 | 정규화 백필로 원문 표기가 범주로 덮어써졌다. 옛 표는 복원 불가 |
| 4.1·4.2 직종 | 재현 | 건수·정렬은 같고 일부 비율이 0.1%p 다르다(반올림) |
| 5.4 정규화된 상병 순위 | 근사 재현 | 공백 제거 + 맨 앞 좌/우/양(측) 제거. 30행 중 24행이 같다(나머지는 아래 표) |
| 6.3 부위 × 부담 부위 | 재현 | 표 191줄 중 5줄만 다르고 모두 15위 경계의 동률 순서 차이다 |
| 5.3 상병군(정규화) | 재현 불가 | 접는 규칙이 `wc/normalize.py`에만 있었고 저장소에 없다 |
| 6.1·6.2·6.4·6.5 텍스트 마이닝 | 재현 불가 | 정규식·키워드 목록이 문서에도 저장소에도 없다(방법론 10.2는 "정규식 추출"이라고만 적었다) |
| 7.1 사례 예시, 8 대표 사례, 9 시사점 | 통계 아님 | 대상이 아니다 |

재현 불가 표를 채우려면 먼저 규칙(키워드·정규식)을 정해 이 문서에 적고, 그 규칙을 `AnalysisReport`에 더한다. 규칙을 임의로 정하면 같은 표가 아니다.

hermes가 쓴 원래 스크립트(`wc/analyze_v2.py` 등)는 다른 서버(`/data/workspace/wc/`)에 있어 저장소에 없다. 저장소 밖에 남은 것은 6.3용 일회성 스크립트 `tmp/bp_crosstab.rb`(CSV 스냅샷 입력, gitignore)뿐이다.
